# AgroAlerta Cañete

Sistema web de control agrícola para Cañete: agricultores, parcelas, cultivos,
campañas, riegos, gastos, cosechas, ventas e indicadores de negocio.

Consúltalo en [`project.md`](project.md) para el alcance completo.

## Estructura

| Ruta | Contenido |
|---|---|
| `frontend/` | React + Vite + Tailwind CSS + React Router |
| `backend/` | API REST con Java 21 + Spring Boot + Maven |
| `database/` | Scripts SQL (esquema de referencia para Supabase) |
| `docs/` | Documentación técnica (API, base de datos, arquitectura) |

## Requisitos

- Java 21 (JDK) y Maven 3.9+
- Node.js 20+ y npm
- Un proyecto **Supabase** con PostgreSQL

## 1. Base de datos (Supabase)

1. Crear el proyecto en Supabase y abrir **SQL Editor**.
2. Pegar y ejecutar [`database/schema.sql`](database/schema.sql) (8 tablas + índices).
   - Las claves primarias **deben ser de identidad** (`BIGINT GENERATED BY DEFAULT AS IDENTITY`).
3. En **Project Settings → API Keys** copiar:
   - `Publishable key` (`sb_publishable_...`) y `Secret key` (`sb_secret_...`).
4. Activar **RLS** en las 8 tablas. El backend usa la clave secreta (bypass RLS
   en el servidor); el publishable solo sirve para lecturas.

## 2. Backend

```powershell
cd backend
copy .env.example .env      # pegar SUPABASE_URL y las dos claves
.\run.ps1                   # arranca en http://localhost:8080
```

`run.ps1` carga `backend/.env` como variables de entorno y ejecuta
`mvn spring-boot:run`. Equivalente manual:

```powershell
$env:SUPABASE_URL="https://TU-PROYECTO.supabase.co"
$env:SUPABASE_PUBLISHABLE_KEY="sb_publishable_..."
$env:SUPABASE_SECRET_KEY="sb_secret_..."
mvn spring-boot:run
```

- Swagger UI: <http://localhost:8080/swagger-ui.html>
- Health: <http://localhost:8080/actuator/health>
- **La persistencia es la API REST de Supabase** (`/rest/v1`, PostgREST) vía
  `SupabaseRestClient`: sin JDBC, sin Hibernate y sin Flyway.
- La clave secreta **solo** vive en el backend; jamás se expone al navegador.
- Si `SUPABASE_SECRET_KEY` está vacía el backend arranca, pero Supabase rechaza
  las escrituras por RLS (`409`).

### Pruebas

```powershell
cd backend
mvn test
```

## 3. Frontend

```powershell
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Configuración en `frontend/.env` (copia de `.env.example`):

```env
VITE_API_BASE_URL=http://localhost:8080/api/v1
```

### Verificación

```powershell
npm run build
npm run lint
```

## 4. Integración

1. Backend levantado y con Supabase conectado.
2. Frontend con `npm run dev`.
3. Probar CRUD completo desde la UI y el dashboard
   (`/api/v1/dashboard/resumen`).

## API

Base: `/api/v1`. Documentación interactiva en Swagger. Resumen completo en
[`docs/api.md`](docs/api.md):

- `/agricultores`, `/parcelas`, `/cultivos`, `/campanas`, `/riegos`, `/gastos`,
  `/cosechas`, `/ventas` → CRUD paginado con filtros.
- `/dashboard/resumen|produccion|ventas|gastos|rentabilidad` → indicadores.

## Seguridad

- CORS restringido a `FRONTEND_URL` (por defecto `http://localhost:5173`).
- Credenciales solo en variables de entorno (`.env` está en `.gitignore`).
- La autenticación con Supabase Auth + JWT en Spring Security está preparada
  pero **no habilitada**: cuando se active, vincular la cuenta mediante un UUID
  adicional **sin reemplazar** `id_agricultor`, y documentar antes las reglas de
  autorización por agricultor.

## Decisiones abiertas (documentadas)

1. **Tipos de datos**: no había diagrama original en el repositorio; se confirmó
   con el usuario usar tipos estándar (`BIGINT` identidad, `VARCHAR`, `DATE`,
   `NUMERIC` con `CHECK >= 0`). Detalle en [`docs/database.md`](docs/database.md).
2. **`campana.fecha_fin` anulable** (campaña en curso) con
   `CHECK (fecha_fin >= fecha_inicio)`.
3. **Sin borrados en cascada**: si hay registros dependientes la API responde
   `409 Conflict` para preservar el histórico.
4. **Autenticación multiusuario** pendiente de definir reglas de autorización.
5. **Desviación de `project.md` (decisión del usuario)**: `project.md` pide
   Spring Data JPA/Hibernate + PostgreSQL JDBC + Flyway. La persistencia se
   implementó con la **API REST de Supabase** (PostgREST) usando las claves
   `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` y `SUPABASE_SECRET_KEY`, porque el
   host de base de datos del proyecto (`db.*.supabase.co`) no es accesible desde
   la máquina de desarrollo y las credenciales de base de datos no son válidas.
   El contrato REST de la API (`/api/v1`, paginación, errores) no cambia.
